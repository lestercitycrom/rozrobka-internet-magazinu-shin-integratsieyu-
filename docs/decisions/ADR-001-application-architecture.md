# ADR-001: базовая архитектура приложения

Статус: accepted  
Дата: 2026-07-31  
Владелец решения: Mister Red

## Контекст

В первоначальном предложении заказчику указан Laravel, MySQL, Redis, очереди и отдельный API-слой. В последующем анализе появился вариант WordPress/WooCommerce + отдельный Laravel-сервис, однако письменного согласования этой замены с заказчиком нет.

Проект имеет сложные интеграции и каталог, но на старте выполняется небольшой командой и в ограниченном бюджете. Два приложения создадут два деплоя, две модели доступа, два набора ошибок и дополнительную синхронизацию.

## Решение

Предлагается модульный Laravel-монолит:

- Laravel как единое приложение;
- MySQL как основная БД;
- Redis для кеша, блокировок и очередей;
- Laravel Queue для импортов и внешних событий;
- отдельные адаптеры NDI, Statens vegvesen, платежей, Notion и Telegram;
- серверный рендеринг/Livewire либо лёгкий frontend без отдельного SPA, если дизайн не докажет необходимость SPA;
- административная панель внутри Laravel;
- versioned internal API только там, где он действительно нужен.

## Последствия

Плюсы:

- соответствует обещанному стеку;
- меньше инфраструктуры и точек отказа;
- проще обеспечить транзакционность заказа;
- быстрее разработка и тестирование небольшой командой;
- интеграции остаются заменяемыми.

Минусы:

- контентная админка потребует реализации/настройки;
- нельзя использовать экосистему WooCommerce без интеграции;
- собственную административную панель и контентные сущности нужно поддерживать внутри приложения.

## Условия пересмотра

Решение пересматривается, если заказчик письменно требует WordPress/WooCommerce, уже имеет обязательные WooCommerce-плагины либо контентная команда должна работать только с WordPress.

## Подтверждение

31 июля 2026 года владелец проекта подтвердил Laravel и дал разрешение начинать разработку. Административная панель разрабатывается полностью самостоятельно внутри Laravel; готовые admin-panel frameworks не используются.
