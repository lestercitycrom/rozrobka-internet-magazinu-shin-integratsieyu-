# ADR-002: стек, структура репозитория и локализация

> Update 2026-07-31: the custom Blade/Tailwind admin shares the storefront's EasyTire design tokens, Ubuntu/Arial typography, logo treatment, density, radii and base components through `application/resources/css/app.css`. No separate admin CSS system, Filament, Livewire, or ready-made admin framework is introduced.

Статус: accepted  
Дата: 2026-07-31  
Владелец решения: Mister Red

## Решение

Проект создаётся как одно Laravel-приложение в каталоге `application/`. Документация, исходные материалы и управленческие артефакты остаются на уровне корня репозитория.

Основной стек:

- Laravel 13 на PHP 8.3 или новее;
- MySQL 8 как основная production-БД;
- Redis 7 для кеша, блокировок и очередей;
- собственная административная панель на Laravel, Blade и Tailwind CSS;
- Blade и Tailwind CSS для витрины; точечный JavaScript добавляется только для действительно интерактивных элементов;
- Pest для unit, feature, integration и architecture-тестов;
- Playwright на TypeScript для E2E-тестов.

Для локальных и автоматических тестов разрешён SQLite там, где тест не проверяет поведение, специфичное для MySQL. Импорт, индексы и запросы каталога дополнительно проверяются на MySQL в CI.

## Локализация

- основная локаль публичной витрины — `nb`;
- административная панель поддерживает интерфейс `nb` и `ru` с переключением пользователем;
- редактируемые контентные сущности проектируются с полями `nb` и `ru`;
- публичные русскоязычные маршруты не включаются до отдельного решения заказчика;
- системная fallback-локаль — `nb`.

Так русский язык помогает владельцу работать в админке, но не меняет согласованный норвежский пользовательский сайт.

## Визуальное направление административной панели

Административная панель остаётся простой и функциональной и полностью разрабатывается командой проекта без Filament, Livewire и других готовых admin-panel frameworks. Она разделяет бело-чёрно-красную фирменную палитру, Ubuntu/Arial, плотность, радиусы и базовые компоненты витрины через общие tokens; отдельная CSS-система не создаётся. Компоненты, навигация, формы, таблицы, роли и состояния принадлежат приложению.

## Правило качества

Каждый новый модуль поставляется вместе с автоматическими тестами. Критический путь считается готовым только при одновременном прохождении:

1. статического форматирования и architecture-тестов;
2. unit/feature/integration-тестов Laravel;
3. Playwright-сценариев покупателя и администратора для изменённого потока;
4. теста идемпотентности для всех импортов, вебхуков и внешних событий.

Запрещены реальные заказы, списания и внешние уведомления из тестов. Для них используются фейки, контрактные фикстуры или официальные песочницы.

## Причины

Текущие стабильные версии дают длительный срок поддержки и не требуют отдельного SPA. Собственная админка сохраняет полный контроль над простотой интерфейса и не связывает проект с готовым административным фреймворком. Размещение приложения в `application/` позволяет безопасно сохранить уже собранные материалы проекта и держать весь продукт в одном репозитории.
