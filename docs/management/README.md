# Организация работы команды

Руководитель и главный архитектор: **Mister Red**  
Инженеры подключаются по отдельным изолированным постановкам Mister Red.

## Распределение ответственности

Mister Red выполняет:

- архитектурные решения;
- аудит и проектирование внешних API;
- модель каталога и совместимости;
- критический поток оплаты и заказа;
- безопасность, идемпотентность и отказоустойчивость;
- сложную диагностику;
- финальное ревью и приёмку.

Mister White получает:

- инвентаризацию материалов и контента;
- изолированные CRUD и административные экраны;
- UI-компоненты по утверждённому прототипу;
- простые импортеры после утверждения mapping;
- unit/feature-тесты по готовому контракту;
- документацию и воспроизводимые чек-листы;
- исправления с чёткими критериями приёмки.

Mister White не меняет архитектуру, API-контракты, схему оплаты или внешние интеграции без решения Mister Red.

Дополнительные роли текущего этапа:

- Mister Black — автоматизация качества и E2E;
- Mister Gray — модель и импорт данных NDI;
- Mister Blue — инвентаризация контента и UX.

## Выбор моделей

- Codex Terra medium/low — окружение, установка, документация, механические изменения и простые CRUD-задачи;
- Codex Terra high — тестовая инфраструктура, модель данных и самостоятельные функциональные срезы средней сложности;
- Codex Sol — только архитектура, критические интеграции, безопасность, платежный/заказный поток и финальное ревью Mister Red.

Модель выбирается по сложности конкретной задачи, а не по должности инженера. Исполнители не создают собственных субагентов без отдельного разрешения Mister Red.

## Каталоги задач

```text
docs/management/tasks/backlog/  — подготовленные, но не начатые задачи
docs/management/tasks/active/   — задачи в работе
docs/management/tasks/review/   — результат передан Mister Red
docs/management/tasks/done/     — принятые задачи
```

Идентификатор задачи: `WHITE-NNN` или `RED-NNN`.

Каждая задача должна содержать:

- цель;
- входные данные;
- границы и запреты;
- ожидаемые файлы/результат;
- критерии приёмки;
- способ проверки;
- зависимости и открытые вопросы.

## Правило перехода

```text
backlog -> active -> review -> done
                     |
                     +-> active, если нужны исправления
```

Никакая задача не считается выполненной только по сообщению разработчика. Mister Red проверяет diff/артефакт, запускает уместные тесты и только после этого переносит её в `done`.
