# RED-020: безопасная граница NDI A2 Inquiry

Исполнитель: Mister Red
Статус: done

## Цель

Зафиксировать проверенную read-only часть Sales API NDI отдельным типизированным модулем, не допуская случайной отправки заказа и утечки учётных данных.

## Результат

- production endpoint и Basic Auth проверены read-only запросом;
- подтверждены точный namespace `http://www.reifen.net`, успешный `quote_A2`, количество и дата поставки;
- фактический ответ не содержит цену, поэтому модуль её не придумывает;
- неверный тестовый `PartyID` корректно возвращает бизнес-ошибку `915`;
- UAT credentials не авторизуются на переданном endpoint;
- отдельные операции резерва и отмены в полученном контракте не подтверждены;
- модуль умеет только Inquiry и по умолчанию выключен;
- разрешён только HTTPS, секреты читаются из environment, DTD запрещён, XML загружается без сети;
- SKU с ведущими нулями сохраняются строкой, XML-метасимволы безопасно проходят round-trip;
- transport, protocol и business errors разделены, response body и credentials не попадают в сообщения исключений.

## Граница готовности

Inquiry-клиент и импорт файлов можно развивать независимо уже сейчас. Checkout не должен вызывать NDI до получения правильного `PartyID`, подтверждения безопасного тестового заказа и правил резерва/отмены. `PlaceOrder` намеренно отсутствует.

## Проверка

- синтетические redacted XML fixtures;
- unit-тесты codec и защит XML;
- Laravel HTTP fake с запретом stray requests;
- ручной production Inquiry только в режиме чтения;
- полный Pest и Playwright запускаются на изолированной базе, без обращения к NDI.
