# Рабочий день и поиск клиентов

Обновлено: 2026-09-14
Область: GitHub Issue #66, поверх модели CRM и автомобилей Issue #65

## Для сотрудника

1. Откройте `Админка → Заявки → Рабочий день`.
2. Выберите дату и ресурс: все задачи, мастерская, выездная машина 1/2 или выезды без назначенной машины.
3. Задачи с подтверждённым временем и желаемым периодом идут по времени Europe/Oslo. Задачи без структурированного времени находятся после них и явно помечены как неподтверждённые.
4. Отменённые заявки скрыты по умолчанию. Их можно показать отдельной галочкой, не меняя сохранённый статус.
5. В карточке видны телефон, адрес, район, все автомобили, госномера, номера комплектов Dekkhotell и операция подготовки. Ссылка на Google Maps выполняет обычный поиск по введённой строке адреса и не является проверенным географическим pin.

В рабочем дне нет автоматического маршрута, распределения машин, складского остатка, изменения времени или финансовых действий. Это оперативное представление уже существующих заявок.

## Полный поиск клиента

В форме заявки клиент больше не загружается из ограниченного списка первых 250 записей. Поле поиска обращается к серверу страницами по 20 результатов и ищет по:

- имени;
- нормализованному телефону;
- e-mail;
- госномеру в явно связанной заявке, включая второй и последующие автомобили.

Выбор меняет только явную связь `client_id`. Контактный снимок заявки не переписывается, автоматического объединения клиентов или назначения владельца автомобиля нет. Госномер в истории означает только то, что он был сохранён в связанной заявке; это не подтверждение текущего владельца.

Ответ lookup содержит только `id` и подпись `имя · телефон`, закрыт от кэширования и доступен только ролям Owner и Operations. Editor, Customer, неактивный пользователь и гость не получают этот доступ.

## Проверка

- Feature: полный поиск, 1001 синтетический клиент, стабильная пагинация, RBAC, отсутствие утечки внутренних полей, номера второго/третьего автомобиля, рабочий день/дата/ресурс/хронология/отменённые.
- Playwright: реальный выбор и сохранение клиента за пределами прежних 250, NB/RU, рабочий день, пять автомобилей, LAST и текстовый номер `00042-A`, ширины 1440/390/320.
- Внешние API, платежи, Telegram, Notion, письма и реальные клиентские данные в этих сценариях не используются.

## Откат

Изменений схемы базы данных в Issue #66 нет. Откат — возврат к предыдущему приложению; данные клиентов и заявок не удаляются.
