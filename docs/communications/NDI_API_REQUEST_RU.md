# Тема: Технические вопросы по NDI Sales API и тестовой среде

Здравствуйте.

Спасибо за доступ и документацию. Мы начали тестировать интеграцию с NDI Sales API.

Авторизация работает, мы получаем доступ к endpoint, WSDL и XSD-схемам. Проблема возникает при отправке сформированного по схеме запроса `inquiry_A2` на адрес:

`https://salesapi.ndias.com/EndPoint`

Сервер отвечает HTTP 200, но в ответе приходит:

```text
There is an error in XML document (0, 0).
```

Та же ошибка возникает при отправке запроса через вашу страницу `servicetest`. Поэтому мы пока не можем получить нормальный ответ `quote_A2` с ценой, остатком и сроком доставки.

Можете, пожалуйста, проверить, связана ли эта ошибка с тестовой средой или с тем, что тестовая учётная запись ещё не полностью активирована?

Для правильного тестирования и реализации интеграции нам также нужны следующие уточнения:

- Можете прислать полный рабочий пример `inquiry_A2` для нашей тестовой учётной записи вместе с ожидаемым ответом `quote_A2`?
- Можете предоставить один действительный тестовый товар, желательно с артикулом NDI и EAN?
- Какие значения необходимо передавать в `BuyerParty/PartyID` и `AgencyCode` для нашей учётной записи?
- Является ли отправка XML напрямую на `/EndPoint` по HTTPS рекомендуемым вариантом для новой интеграции? SOAP C1 методы на тестовой странице отмечены как устаревшие.
- В WSDL для `Service.svc` указан HTTP-адрес. Можете подтвердить, что в рабочей среде весь обмен должен выполняться через HTTPS, и указать официальный endpoint?
- Всегда ли `quote_A2` возвращает актуальную закупочную цену, доступное количество и ожидаемую дату доставки?
- Есть ли отдельный метод резервирования товара до оплаты?
- Можно ли отменить заказ через API? Если да, какое сообщение или метод нужно использовать?
- Какой метод вы рекомендуете для получения статуса заказа: `NDIStatus`, `GetOrderDespatch` или другой?
- Есть ли ограничения на количество запросов и количество позиций в одном `inquiry` или заказе?
- Какие значения timeout и правила повторных запросов вы рекомендуете?

Перед тестированием создания заказа мы также хотим получить подтверждение, что заказы в тестовой среде останавливаются и не передаются в реальную обработку. Если возможно, пришлите пример тестового заказа и соответствующего ответа или сообщения о статусе.

Как только мы получим рабочий пример inquiry/quote, мы проверим весь процесс и быстро сообщим, если обнаружим дополнительные вопросы.
