Статус документа: рабочая версия после первичного ознакомления

Ответственный: Mister Red

## Цель

Создать норвежский сайт EasyTire, который объединяет:

- продажу шин, дисков и колёсных комплектов;
- подбор автомобиля по регистрационному номеру;
- подбор по штатным размерам и ручной поиск по размеру;
- актуальные цены, остатки и сроки поставки NDI;
- корзину, дополнительные услуги и онлайн-оплату;
- запись на услуги;
- передачу оплаченного заказа в Notion;
- уведомления в Telegram;
- редактируемый контент и SEO-страницы услуг в Tromsø.

## Уже подтверждено

- Действующий EasyTire — контентный сайт на Tilda с услугами, ценами и несколькими сценариями записи.
- NDI предоставляет каталог и склад файловыми выгрузками через SFTP. По письму NDI файлы обновляются один раз в сутки.
- NDI Sales API работает по EDIWheel и предназначен для inquiry/quote, размещения заказа и получения информации об отгрузке.
- NDI не осуществляет B2C-доставку конечному покупателю. В текущей договорной схеме доступны самовывоз и доставка в согласованную точку/зону.
- Для поиска автомобиля существует отдельный официальный API Statens vegvesen, который возвращает технические данные и одобренные комбинации шин и дисков.

## Принятое архитектурное решение

Проект реализуется как **модульный Laravel-монолит**, а не два независимых приложения WordPress + Laravel:

- это прямо соответствует первоначально заявленному заказчику стеку;
- одна кодовая база проще для небольшой команды, текущего бюджета и срока;
- каталог, checkout, запись, интеграции, очереди и админка остаются в одной транзакционной системе;
- NDI, Statens vegvesen, платежи, Notion и Telegram всё равно отделяются интерфейсами и адаптерами;
- при реальной необходимости интеграционный модуль позже можно вынести в отдельный сервис без изменения бизнес-контракта.

Предлагаемые модули:

Решение подтверждено владельцем проекта 31 июля 2026 года. Административная панель разрабатывается командой самостоятельно; готовые admin-panel frameworks запрещены.

## Источники истины

- Laravel/MySQL: нормализованный каталог, правила цены, корзины, заказы, статусы интеграций.
- NDI CSV/SFTP: массовые данные поставщика.
- NDI Inquiry/Quote: оперативная проверка известного артикула перед заказом.
- Statens vegvesen: автомобиль и разрешённые комбинации.
- Админка Laravel: тексты, изображения, услуги, SEO, правила наценки.
- Notion: операционная копия заказа, но не основная база.

## Главные ограничения

- NDI API не заменяет каталог и не предоставляет поиск товаров по фильтрам.
- В опубликованном контракте NDI не найдены отдельные операции резерва и отмены.
- Успешный read-only Inquiry подтверждён на рабочем endpoint: получены количество и дата поставки; цена в фактическом ответе отсутствует.
- Без резервирования остаётся гонка между проверкой остатка, оплатой и созданием заказа NDI.
- Оригинальные документы, XML-примеры и три файловые выгрузки NDI получены и разобраны. Не получены SFTP-доступ и правильный `PartyID` EasyTire.
- Платёжный провайдер выбран: Dintero Checkout. Тестовый account/client получен; схема authorization без auto-capture и ручного capture после получения/готовности товара подтверждена заказчиком. Production всё ещё требует KYC, production client/profile, сроков резерва по методам оплаты и утверждённых правил отмены/refund.

## Ближайшие контрольные точки

1. Поднять каркас Laravel, автоматические тесты и staging с автоматическим деплоем.
2. Реализовать сырой слой и идемпотентный импорт файлов NDI по принятой модели данных.
3. Реализовать собственную административную оболочку и отчёт импорта на `nb`/`ru`.
4. Получить у NDI правильный `PartyID`, SFTP-доступ и правила актуальности цены.
5. Согласовать с NDI безопасный тест заказа и проверить ответ, не создавая боевую поставку.
6. Получить ключ Statens vegvesen и проверить реальный ответ по номеру автомобиля.
7. Протестировать Dintero sandbox end-to-end, зарегистрировать callback signature и затем пройти отдельный production acceptance без изменения прикладного кода.
